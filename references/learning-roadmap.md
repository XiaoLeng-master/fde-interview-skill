# 自适应 FDE 学习路线

## 路线不是课程清单

学习目标是形成可投递、可追问、可运行的证据。每个阶段必须交付可检查产物；“读完十篇文章”不算完成。

## 先判断候选人类型

| 背景 | 常见优势 | 常见缺口 | 优先补强 |
| --- | --- | --- | --- |
| SWE/Infra | 编码、系统、调试 | Discovery、价值、采用 | 客户 Case 与项目重构 |
| Data/ML | 数据、模型、实验 | 应用工程、权限、运营 | 端到端服务与运行控制 |
| Agent Engineer | RAG/Agent/Eval | 真实客户、业务指标、复用 | 真实工作流和采用证据 |
| Solutions/Consulting | 客户、范围、沟通 | Coding、生产工程 | 可运行项目与系统设计 |
| Implementation | 集成、交付 | 产品判断、复用、技术深度 | 机制取舍和产品回流 |
| Product/Business/CS/Ops/Domain | 用户、流程、采用或领域 | Coding、API、数据、生产责任 | 渐进最小技术路径＋领域工作流 |
| Beginner/Early career | 学习速度、可塑性 | 工程、生产和客户证据 | 渐进最小技术路径＋模拟项目 |

## 渐进最小技术路径

面向零基础和非技术候选人，目标不是先学完整 CS 课程，而是逐层获得 Delta 证据。每层通过验收后再进入下一层；无法完成当前层时，不用 Agent 框架掩盖基础缺口。

| 层级 | 最小能力 | 验收产物 |
| --- | --- | --- |
| 0. 流程与数据 | 画真实流程、定义输入输出/异常/Owner；表格与基础数据清洗 | 一个脱敏 Workflow、10 个代表性 Case、基线和验收事件 |
| 1. 编程与版本 | 一门主语言、命令行、Git、测试、读错误信息 | 可重复运行的脚本；至少 3 个测试；能复现并修复一个失败 |
| 2. 数据与接口 | SQL、JSON、HTTP/API、认证、参数校验 | 读取一个 API/数据库，写入暂存区；错误可理解且无敏感日志 |
| 3. 可运行服务 | Web 服务、数据库、状态、异步任务、部署 | 一条端到端 Vertical Slice；有配置、日志和部署说明 |
| 4. 受控生产 | 身份权限、幂等、观测、发布、回滚、Runbook | 权限矩阵、失败恢复、监控、一次事故演练与回滚证据 |
| 5. 目标专项 | 只学习 JD 所需的 RAG/Agent、Data Platform、Cloud 或行业系统 | 离线 Eval、机制取舍、成本/风险和人工兜底 |

最低进度原则：申请需要亲手编码的初级 FDE 前，至少完成层级 0–3；声称生产交付前必须完成层级 4；层级 5 不能替代 1–4。对尚未达到门槛的人，优先建议 `role-model.md` 中的相邻路线，并明确哪些证据以后可迁移。

## 路线选择

### 14 天面试冲刺

选择条件：已有强工程证据，且至少有一项真实上线、客户协作或生产排障经历；主要问题是岗位翻译和面试表达。

- 第 1–2 天：审计 JD、简历和证据，建立双轨定位。
- 第 3–5 天：重写一个项目 Case，补架构、故障、指标、采用和复用说明。
- 第 6–8 天：完成一个 3–4 小时陌生产品排障/客户回复练习。
- 第 9–11 天：Discovery、System Design、Production 三类 Case。
- 第 12–14 天：完整 Mock、简历收口和针对性投递。

验收：两版简历、一个完整 Case Study、一份客户邮件、一份设计/运行文档、两次模拟面试记录。

### 28 天结果优先冲刺

选择条件：有研发或交付基础，但缺少完整 FDE 闭环或可信作品集。

- 第 1 周：角色定位、证据审计、简历初版、Capstone Brief；第 7 天开始投递。
- 第 2 周：完成真实工作流的 Vertical Slice，包含接口、数据、状态和失败路径。
- 第 3 周：加入 Eval、权限、观测、成本、人工兜底、发布门禁和回滚。
- 第 4 周：加入采用和复用方案，制作 Demo、Case Study，并进行双轨面试。

验收：可运行系统、测试/Eval、威胁模型、发布/回滚、Runbook、采用计划、复用提案、双轨简历和演示。

### 6–8 周基础计划

选择条件：Coding、Web/API、数据库、部署或生产运行中存在硬缺口，或目标岗位级别明显高于现有证据。

- 第 1–2 周：按渐进路径完成层级 0–1：真实流程、一门主语言、Git、测试与调试。
- 第 3 周：完成层级 2：SQL、HTTP/API、数据库、认证和外部系统集成。
- 第 4 周：完成层级 3–4：服务、权限、异步任务、部署、日志、指标和故障恢复。
- 第 5 周：RAG/Agent 或目标平台专项，建立离线 Eval。
- 第 6 周：客户 Discovery、范围和价值 Case。
- 第 7 周：生产化 Capstone 和事故演练。
- 第 8 周：作品集、Mock 和岗位投递。

验收：一个端到端系统、一份运行手册、一套 Eval、一个客户 Case、一次英文或国内现场演练。

## 自定义期限

如果用户只有 N 天：

1. 先保留硬门槛和最高影响证据。
2. 复用已有项目，不为展示而新造复杂系统。
3. 从准备周期的前 25% 开始小批量投递，用真实反馈修正路线。
4. 把长期能力缺口明确标记，不用话术掩盖。

如果用户每天时间有限，按以下优先级分配：

```text
证据整理与项目产物 40%
Case/面试练习 30%
针对性技术补强 20%
投递与复盘 10%
```

## Capstone 选择规则

优先改造已有项目或真实工作流。一个合格题目必须有：明确用户、高频任务、现状流程、可测基线、数据/系统接口、至少一个失败风险、Owner 和验收方式。

避免：泛用聊天机器人、只展示 Prompt、没有数据权限、没有写入边界、没有用户和业务事件的 Demo。

最小作品集：

```text
problem-brief.md
current-workflow.md
architecture.md
eval-plan.md
threat-model.md
rollout-and-rollback.md
runbook.md
adoption-plan.md
reusable-assets.md
src/ tests/ evals/
```

## 动态调整

- 已有生产系统：少造项目，多提取事故、权衡、采用和复用证据。
- 已有客户交付：补 Coding、测试、架构与平台化证据。
- 只有 Demo：把一条路径做深，加入真实失败、权限、Eval 和运行责任。
- 目标 JD 偏 Data/Platform：减少通用 Agent 内容，增加 SQL、Pipeline、Cloud 和治理。
- 目标 JD 偏 AI FDE：增加 Tool、State、Eval、Tracing、Guardrail、Cost 和 Human Oversight。
- 目标国内：增加现场观察、私有化、非标准系统和短 PoC。
- 目标国际：增加英文、Coding、System Design、Multi-tenant 和 Upstreaming。

## 每周复盘

只问五个问题：

1. 新增了什么招聘方可检查的证据？
2. 哪个缺口仍只有术语，没有行为或产物？
3. 哪次投递或模拟暴露了真正 Gate？
4. 下周应删掉什么低价值学习？
5. 哪个成果可以转成复用模板或第二个 Case？
